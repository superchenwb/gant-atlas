# 主页面文档规格

## 一、适用范围

适用于主页面、列表页、SearchForm + Grid 页面，以及多 Tab 主页面。

## 二、文档目标

主页面文档只描述页面事实：

- 页面用途
- 页面结构
- 查询区
- 按钮区
- 表格区
- Tab / 区域拆分
- 弹窗
- 接口链路
- 特殊限制

不写测试脚本、自动化契约或执行深度。

## 三、完整性要求

主页面不能只做区域级总览，必须把每一个具体功能点逐项写全。

至少包括：

1. 每个查询字段
2. 每个页面按钮
3. 每个 Tab 内按钮
4. 每个表格列
5. 每个行操作按钮
6. 每个单元格点击行为
7. 每个弹窗入口
8. 每个独立可见模块
9. 每个明显的联动、校验、状态切换、刷新行为

禁止只写：

- “支持新增、编辑、删除”
- “表格有操作列”
- “有弹窗”
- “有其他功能模块”

必须继续展开到具体功能项。
## 四、页面拆分原则

满足以下任一情况时必须拆分：

1. 存在多个 Tab，且每个 Tab 有独立按钮或表格
2. 存在多个独立 Grid
3. 单个弹窗内容较大
4. 页面存在独立树区、汇总区、附件区或说明区

拆分原则：

- 一个独立交互域对应一份独立文档
- `main.md` 只做总览与导航
- 只要同时存在按钮区和表格 / 主内容区，就必须拆成独立按钮文档和表格文档
- Tab 内按钮区和表格区必须拆开写，不能混在同一个 `main.md` 里代替详细描述
- 按钮功能复杂时，按钮本身也可以单独成 `button-{name}.md`
- 如果按钮点击后打开复杂弹窗，优先把按钮与弹窗合并写进 `button-{name}.md`
- 只有弹窗需要跨按钮复用或必须独立表达时，才单独成 `popup-{name}.md`

## 五、主页面必须覆盖的内容

### 5.1 页面概述

- 页面中文名
- 页面英文名或目录名
- 页面功能
- 页面类型
- 所属模块
- 路由地址
- 默认展示状态
- 全页面功能索引

`main.md` 必须增加“全页面功能索引”章节，至少列出：

- 页面级按钮
- 复杂按钮文档
- 各 Tab
- 各 Tab 内主要按钮
- 各 Tab 内主表格或主内容区
- 独立可见模块
- 复用型弹窗或独立弹窗

### 5.2 页面结构

必须在 `main.md` 中输出页面结构图，使用文本框图或等价的结构化示意。

结构图至少覆盖：

- 查询区域
- 页面级按钮
- 主表格或主内容区
- 其他可见模块
- 各 Tab 或各子区域

补充要求：

- 多 Tab 页面要把主要页签名称画出来。
- 单 Grid 页面要体现查询区、按钮区、主内容区的上下关系。
- 页面存在左右按钮分区时，要在结构图中体现。

### 5.3 查询区域

必须覆盖：

- 字段标签
- 参数名
- 控件类型
- 默认值
- 占位提示
- 必填与只读/禁用
- 字段联动
- 查询参数转换
- 查询后的页面结果

每一个查询字段都必须单独描述，不能只写“包含若干查询条件”。

### 5.4 按钮区域

必须覆盖：

- 按钮名称
- 所属范围
- 位置
- 显示条件
- 禁用条件
- 点击结果
- 二次确认
- 打开弹窗还是直接处理

每一个按钮都必须单独描述，不能只写“左侧按钮组 / 右侧按钮组”。

全局规则：

- 只要页面存在按钮区和表格 / 主内容区，按钮功能主描述必须放在按钮文档，不得混入表格文档。
- 如果某个按钮功能本身很大、步骤多、状态分支多、涉及多个入口或多个结果，必须单独成 `button-{name}.md`。
- 如果按钮点击后打开弹窗，而这套“按钮 + 弹窗”功能复杂，优先在同一个 `button-{name}.md` 中完整描述。
- 按钮文档必须包含状态差异矩阵，至少覆盖权限状态、数据状态、选中状态、页面状态中的关键差异。

如果按钮属于某个 Tab：

- 该按钮优先写在对应 `tab-{name}/button-area.md`
- 不要把 Tab 内按钮混写进 `tab-{name}/grid-area.md`
- 复杂按钮允许继续拆成 `tab-{name}/button-{name}.md`
- 按钮打开的弹窗如果复杂，优先合并进 `tab-{name}/button-{name}.md`
- 按钮打开的弹窗如果不复杂，也要在按钮文档里把字段、联动、校验、提交结果写完整
- 只有复用型或必须独立表达的弹窗才单独成 `popup-{name}.md`

### 5.5 表格区域

必须覆盖：

- 列标题
- 字段名
- 展示内容
- 是否可编辑
- 行选择规则
- 行操作
- 单元格点击行为
- 行内联动与校验
- 表格相关接口

每一个行操作、每一个单元格点击行为都必须单独描述。

Tab 内的 `grid-area.md` 只负责表格和主内容区事实：

- 列
- 行操作
- 单元格点击
- 编辑规则
- 联动校验
- 表格相关接口

不要把按钮功能主描述放进 `grid-area.md`。

同样地，页面级 `grid-area.md` 也不能承担按钮功能主描述。

`grid-area.md` 必须补充状态差异矩阵，至少覆盖：

- 空态 / 非空态
- 未选中 / 单选 / 多选
- 编辑态 / 非编辑态
- 关键行状态差异

### 5.6 弹窗

必须覆盖：

- 标题
- 触发入口
- 打开条件
- 字段或子表格
- 联动
- 校验
- 提交结果

每一个弹窗入口都必须能在主文档或对应子文档中找到完整描述。

如果弹窗由某个按钮独占触发，且按钮功能复杂：

- 优先把弹窗完整内容写进对应按钮功能文档
- 不强制再拆出单独弹窗文档

### 5.7 其他可见模块

例如：

- 左侧树
- 汇总卡片
- 附件区
- 对比区
- 独立说明区

每一个独立模块都要写清用户能做什么、触发后发生什么。

`other-features.md` 必须补充：

- 模块内子功能索引
- 模块状态差异矩阵或等价清单
## 六、接口归类规则

接口只按前端触发场景归类：

- 页面初始化
- 查询
- 页面级按钮
- 表格行操作
- 弹窗提交

不要把所有 service 直接堆到一个列表里。

## 七、写作约束

1. 只写页面事实，不写实现细节说明。
2. 不保留源码路径、导入路径、组件名、Hook 名。
3. 无法确认的内容写 `[待确认]`。
4. 不要因为共享组件被封装，就停止在“共享组件内部定义”。
5. 必须继续追到页面真实展示内容。
6. 不允许只写概述而省略具体功能项。
## 八、对应模板

主页面通常使用：

- `templates/page-main/main.md`
- `templates/page-main/search-area.md`
- `templates/page-main/button-area.md`
- `templates/page-main/grid-area.md`
- `templates/page-main/other-features.md`

弹窗较复杂时补：

- `templates/common/popup.md`
