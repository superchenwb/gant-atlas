# 组件文档规范 (component-spec)

本规范定义业务组件功能文档的内容边界、必须覆盖的维度和禁止事项。

---

## 适用范围

适用于 `packages/*/src/components/**` 下的业务组件，以及 `packages/procomponents/src/business/**` 下的框架业务组件，和其他非页面级、可被多处引用的独立组件。

不适用于：
- 页面级组件（已有 page-main / page-detail 规范）

---

## 文档输出路径

```text
packages/<pkg>/src/components/<componentDir>/
-> docs/<pkg>/components/<componentDir>/main.md

packages/procomponents/src/business/<componentDir>/
-> docs/procomponents/business/<componentDir>/main.md
```

---

## 简单组件 vs 复合组件判定

| 判定条件 | 分类 | 文档结构 |
|----------|------|----------|
| 仅含 Props + 简单交互，无 Grid/SearchForm/多按钮多弹窗/表单 | 简单组件 | 单个 `main.md` |
| 含 Grid 表格 | 复合组件 | `main.md` + `grid-area.md` |
| 含操作按钮（含弹窗） | 复合组件 | `main.md` + `button-area.md` 或 `button-{name}.md` |
| 含搜索表单 | 复合组件 | `main.md` + `search-area.md` |
| 含编辑/展示表单 | 复合组件 | `main.md` + `form-area.md` |
| 含多个上述区域 | 复合组件 | `main.md` 导航 + 对应子文档 |

**子文档类型不限于上表列举**。当组件内存在其他独立可见的功能区域（如统计面板、树形结构、时间线等），也应按相同原则拆分为 `{area-name}-area.md`。判断标准：该区域有独立的字段/交互/逻辑需要逐项描述，且内容量足以独立成文。

当组件满足以下任一条件时，`main.md` 必须包含功能索引与文档导航章节：
- 组件内有 Grid 表格
- 组件内有 2 个及以上操作按钮
- 组件内有弹窗/抽屉
- 组件内有搜索表单
- 组件内有编辑表单
- 组件内存在其他需要独立描述的功能区域

## 必须覆盖的内容

### 1. 组件概述

- 一句话说明组件的核心用途
- 说明组件的基本形态

### 2. Props 接口

以表格形式列出所有对外暴露的 Props：

| 字段 | 要求 |
|---|---|
| 参数名 | 和代码保持一致 |
| 类型 | 用语义化描述，不要写 TS 泛型细节 |
| 是否必填 | 是 / 否 |
| 默认值 | 有则填写，无则填"-" |
| 说明 | 描述该参数的用途，不写参数的内部处理方式 |

### 3. 功能索引与文档导航（仅复合组件）

复合组件的 `main.md` 必须包含：

- **功能索引表**：列出组件的全部功能，每项包含功能名称、触发入口、所属区域、关键条件、对应文档链接
- **文档拆分清单**：列出拆分的子文档及其对应的区域

简单组件跳过此节。

### 4. 交互行为

描述组件对外暴露的每一种用户交互，每种交互单独列出：

- **触发方式**：用户如何触发
- **组件响应**：组件界面发生什么变化
- **回调触发**：是否向外部触发回调

### 5. 数据流与逻辑

从调用方可观察的角度描述：

- **数据加载时机**：何时加载数据
- **加载失败处理**：加载失败时组件呈现何种状态
- **可见状态列表**：组件具有哪些可见的外部状态及对应展示形式
- **关键时机**：重置时机、数据初始化时机、依赖参数变化时的重新加载行为

### 6. 使用场景

- 组件适合在哪些页面类型或功能场景中使用
- 有无使用前提条件
- 引用的其他组件（只写文档路径）

### 7. 引用的其他组件文档

以表格列出组件中引用的其他组件及其文档路径。不描述被引用组件的内部组成。

## 组件专属 Hook 与文档的关系

组件内 `hooks/` 目录下的 Hook 是 UI 功能的具体实现（如 `useBatchOperations` 实现了转发/调整/跳过按钮的功能）。

**核心规则**：
- 组件专属 Hook **不独立建档**
- 其功能已在组件文档的按钮清单（`button-area.md` 或 `button-{name}.md`）中描述
- 文档描述的是**功能**（按钮做什么），不是**实现**（Hook 怎么做）
- 只有模块级共享 Hook（位于 `src/hooks/` 下，被多个组件/页面共用）才需要独立文档

---

## 跨组件引用规则

组件文档中引用其他组件时：
- **只写被引用组件的文档路径**
- **不描述被引用组件的内部组成、Props、交互行为等**
- 示例：`→ [审批流程表格文档](../../workflowapproval/approvalprocessgrid/main.md)`

---

## 禁止事项

1. **禁止写内部实现细节**：不写 Hook 名称、Store 变量名、内部状态变量名
2. **禁止写源码引用**：不写"详见 useXxx""参见 store.ts"
3. **禁止写 CSS 实现**：不描述样式类名、CSS 变量、样式 Token
4. **禁止写框架内部机制**：不描述 procomponents 框架的底层行为
5. **禁止摘要代替具体**：不能只写"支持选择""支持回调"，必须展开到每种交互的具体行为
6. **禁止伪造**：无法确认的内容写 `[待确认]`，不要猜测
7. **禁止描述被引用组件的内部**：引用其他组件时只写文档路径，不展开其组成

---

## 内容完整性检查

- [ ] 组件概述已说明核心用途和形态
- [ ] Props 表已覆盖所有对外暴露的参数
- [ ] 复合组件 `main.md` 已包含功能索引与文档导航
- [ ] 复合组件的 Grid 区域已拆分为 `grid-area.md`，每列单独一行
- [ ] 复合组件的按钮区域已拆分为 `button-area.md`，每按钮单独一行
- [ ] 复合组件的搜索区域已拆分为 `search-area.md`（如含搜索表单）
- [ ] 复合组件的表单区域已拆分为 `form-area.md`（如含编辑/展示表单）
- [ ] 复合组件的其他独立功能区域已拆分为对应的 `{area-name}-area.md`
- [ ] 复杂按钮 + 弹窗已合并到 `button-{name}.md` 一体化文档
- [ ] 每一种用户交互都有独立描述（触发方式 + 响应 + 回调）
- [ ] 数据加载时机和加载失败处理已描述
- [ ] 可见状态（加载中/禁用/选中等）已列全
- [ ] 使用场景和前提条件已说明
- [ ] 引用的其他组件只写了文档路径，未展开其组成
- [ ] 文档中无 Hook 名、Store 名、源码路径等实现细节
- [ ] 组件专属 Hook 未独立建档

## 特殊情况处理

### 选择器类组件（Select / TreeSelect / LoupeSelect 封装）

除通用维度外，额外说明：
- 下拉选项的数据来源描述（来自某个业务数据集，不写 API 路径）
- 是否支持搜索，搜索行为
- 选中值的格式

### 按钮类组件（AddButton / DeleteButton 等封装）

除通用维度外，额外说明：
- 按钮触发的主操作流程
- 权限控制条件
- 操作成功/失败后的页面反馈

### Grid 类组件（内嵌 Grid 的复合组件）

除通用维度外，必须拆分 `grid-area.md` 子文档，包含：
- 表格列清单（每列单独一行：列标题、字段名、展示类型、格式规则、条件）
- 可编辑列及编辑规则
- 行操作清单（每按钮单独一行）
- 单元格点击行为
- 表格联动与校验

### 复合组件文档拆分规则

- 复合组件的 `main.md` 必须包含功能索引和文档导航
- 只要组件内同时存在按钮区和表格/主内容区，就必须分开描述
- 复杂按钮 + 弹窗优先合并到 `button-{name}.md`
- 只有复用型弹窗才单独生成 `popup-{name}.md`
- 组件专属 Hook 不独立建档，其功能在按钮清单中描述
- 子文档类型按组件实际包含的功能区域确定，不限于 `grid-area` / `button-area` / `search-area` / `form-area`：
  - 含表格 → `grid-area.md`
  - 含按钮 → `button-area.md`（复杂按钮拆为 `button-{name}.md`）
  - 含搜索表单 → `search-area.md`
  - 含编辑/展示表单 → `form-area.md`
  - 其他独立功能区域 → `{area-name}-area.md`（如 `tree-area.md`、`statistics-area.md` 等）
- 拆分判断标准：该区域有独立的字段/交互/逻辑需要逐项描述，且内容量足以独立成文
