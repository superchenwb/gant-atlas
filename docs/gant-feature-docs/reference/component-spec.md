# 组件文档规范 (component-spec)

本规范定义业务组件功能文档的内容边界、必须覆盖的维度和禁止事项。

---

## 适用范围

适用于 `packages/*/src/components/**` 下的业务组件，以及其他非页面级、可被多处引用的独立组件。

不适用于：
- 页面级组件（已有 page-main / page-detail 规范）
- procomponents 框架内部组件

---

## 文档输出路径

```text
packages/<pkg>/src/components/<componentDir>/
-> packages/<pkg>/docs/components/<componentDir>/main.md
```

---

## 必须覆盖的内容

### 1. 组件概述

- 一句话说明组件的核心用途
- 说明组件属于哪个业务领域（如：BOM 选择、变更单操作等）
- 说明组件的基本形态（弹窗选择器、内嵌表格、按钮组等）

### 2. Props 接口

以表格形式列出所有对外暴露的 Props：

| 字段 | 要求 |
|---|---|
| 参数名 | 和代码保持一致 |
| 类型 | 用语义化描述，不要写 TS 泛型细节（如写"字符串"而非 `string`，写"对象数组"而非 `T[]`） |
| 是否必填 | 是 / 否 |
| 默认值 | 有则填写，无则填"-" |
| 说明 | 描述该参数的用途，不写参数的内部处理方式 |

### 3. 交互行为

描述组件对外暴露的每一种用户交互，每种交互单独列出：

- **触发方式**：用户如何触发（点击按钮、输入文字、滚动等）
- **组件响应**：组件界面发生什么变化（弹窗打开、列表刷新、状态切换等）
- **回调触发**：是否向外部触发回调（触发 onChange、onConfirm 等的时机，以及传出的数据内容）

### 4. 数据流与逻辑

从调用方可观察的角度描述：

- **数据加载时机**：何时发起数据请求（组件挂载时、用户触发时、参数变化时等）
- **加载失败处理**：加载失败时组件呈现何种状态（空状态、错误提示等）
- **可见状态列表**：组件具有哪些可见的外部状态（加载中、禁用、选中、空态等）及对应展示形式
- **关键时机**：重置时机、数据初始化时机、依赖参数变化时的重新加载行为等

### 5. 使用场景

- 组件适合在哪些页面类型或功能场景中使用
- 有无使用前提条件（如需要特定权限、需要父组件提供某上下文等）
- 与其他组件配合使用时的注意事项

---

## 禁止事项

1. **禁止写内部实现细节**：不写 Hook 名称、Store 变量名、内部状态变量名
2. **禁止写源码引用**：不写"详见 useXxx""参见 store.ts"
3. **禁止写 CSS 实现**：不描述样式类名、CSS 变量、样式 Token
4. **禁止写框架内部机制**：不描述 procomponents 框架的底层行为
5. **禁止摘要代替具体**：不能只写"支持选择""支持回调"，必须展开到每种交互的具体行为
6. **禁止伪造**：无法确认的内容写 `[待确认]`，不要猜测

---

## 内容完整性检查

- [ ] 组件概述已说明核心用途和形态
- [ ] Props 表已覆盖所有对外暴露的参数
- [ ] 每一种用户交互都有独立描述（触发方式 + 响应 + 回调）
- [ ] 数据加载时机和加载失败处理已描述
- [ ] 可见状态（加载中/禁用/选中等）已列全
- [ ] 使用场景和前提条件已说明
- [ ] 文档中无 Hook 名、Store 名、源码路径等实现细节

## 特殊情况处理

### 选择器类组件（Select / TreeSelect / LoupeSelect 封装）

除通用维度外，额外说明：
- 下拉选项的数据来源描述（来自某个业务数据集，不写 API 路径）
- 是否支持搜索，搜索行为（本地过滤 / 远程搜索）
- 选中值的格式（单值 / 多值 / 对象）

### 按钮类组件（AddButton / DeleteButton 等封装）

除通用维度外，额外说明：
- 按钮触发的主操作流程（完整描述：确认弹窗 → 请求 → 刷新等）
- 权限控制条件（有则说明显示/隐藏/禁用规则）
- 操作成功/失败后的页面反馈

### Grid 类组件（内嵌 Grid 的复合组件）

除通用维度外，额外说明：
- 表格列清单（列名、数据类型、特殊展示规则）
- 可编辑列及编辑规则
- 行操作清单
